# Нефтяные данные Hyperliquid

Первая часть будущего аналитического агента: поиск рынков, загрузка минутных
свечей и сохранение графика. Сделок программа не совершает. Кошелёк и API-ключ
не нужны. Требуется Python 3.10+. Загрузка через API использует стандартную
библиотеку; для импорта больших архивов Parquet дополнительно нужен DuckDB.

## Как пользоваться

Откройте терминал и перейдите в папку проекта:

```sh
cd /workspace/my-project
python oil_agent.py markets
```

Команда ищет BRENT, OIL и WTI среди основной площадки и дополнительных
perpetual DEX. Это разные инструменты: название OIL само по себе не доказывает,
что контракт отслеживает Brent. Сверьте описание контракта на сайте.
Поле `coin` — точное имя для API; сохраните префикс перед двоеточием, если он есть.
`collateral_token_index` — индекс обеспечения, а не подтверждение USDC.

Затем подставьте выбранное имя вместо `ТОЧНОЕ_ИМЯ`:

```sh
python oil_agent.py fetch --coin 'ТОЧНОЕ_ИМЯ' --hours 24
```

В папке `data` появятся три файла:

- CSV — таблица времени, открытия, максимума, минимума, закрытия и объёма.
- JSON — данные и сведения о запросе для дальнейших вычислений.
- HTML — свечной график, который можно скачать и открыть браузером без интернета.

График показывает шкалы цен с обеих сторон и время снизу. При наведении
появляются точные цены открытия, максимума, минимума и закрытия; максимум
и минимум дополнительно подписаны рядом со свечой. Колесо мыши и кнопки
＋/− меняют масштаб, перетаскивание и ползунок перемещают по истории.
Кнопка «Весь период» показывает все данные. Часовой пояс по умолчанию —
Москва; можно переключить на UTC. График — сохранённый снимок, а не онлайн-трансляция.
Шаблон `chart_template.html` должен находиться рядом с `oil_agent.py` при создании
новых графиков; готовый HTML полностью самодостаточен.

Свечи содержат только завершённые минуты. Время записано в UTC. Пропуски
не заполняются выдуманными ценами; число недостающих минут показывается явно.
API предоставляет только последние 5000 свечей: здесь запрос ограничен 80 часами.
Для длинной истории понадобится регулярный сбор и накопление данных.
Расчёт корреляций и работа по расписанию пока не реализованы.

## Проверка

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements-archive.txt
.venv/bin/python -m unittest discover -s tests -v
```

Тесты используют искусственные данные и не доказывают доступность биржи.
Для проверки подключения выполните `markets`, затем `fetch` с реальным именем.
Ошибка `Tunnel connection failed: 403 Forbidden` означает блокировку облачным
сетевым прокси. В настройках среды разрешите `api.hyperliquid.xyz`, сохраните
изменение и повторите команду. Ключи и пароли для этих запросов не требуются.

## Импорт архива 0xArchive

`archive_import.py` читает HIP-3 Trades Parquet и создаёт CSV, JSON с отчётом
и автономный HTML-график с кнопкой «Сохранить график» внутри страницы.
Сам файл остаётся неизменным. Подготовьте `.venv` командами выше, затем:

```sh
cd /workspace/my-project
.venv/bin/python archive_import.py '/путь/к/xyz_BRENTOIL_trades_2026-03-04_to_2026-10-14.parquet' --output data/archive
```

В Windows команды установки и запуска из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-archive.txt
.\.venv\Scripts\python.exe archive_import.py "C:\Users\ИМЯ\Downloads\xyz_BRENTOIL_trades_2026-03-04_to_2026-10-14.parquet" --output data\archive
```

Имя пользователя и путь нужно заменить на фактические. В папке проекта должны
лежать `archive_import.py`, `oil_agent.py`, `chart_template.html` и
`requirements-archive.txt`. В консоли Windows должен быть доступен Python 3.10+.

Обработка использует временную базу на диске рядом с результатами, два потока
и ограничение памяти DuckDB 512 МБ (`--memory-mb`). Это ограничение DuckDB,
а не всего процесса Python. Понадобится свободное место для временных файлов;
точный объём зависит от числа сделок. Результаты предыдущего запуска не
перезаписываются: для повторного импорта укажите новую папку `--output`.

Правила построения свечей:

- Две стороны одной сделки объединяются по `trade_id`, объём считается один раз.
  Несовпадающие время, цена или размер у одинакового ID останавливают импорт.
- Проверяются символ, наличие столбцов, время с часовым поясом и значения цен/размеров.
- Внебиржевые переносы позиций (ADL, backstop, settlement и другие перечисленные
  в документации 0xArchive операции) не создают торговые свечи.
- В свечу попадают сделки от начала минуты включительно до следующей минуты
  исключительно. Текущая незавершённая минута исключается.
- В одну миллисекунду сделки упорядочиваются по их позиции в исходном файле.
  Это воспроизводимый порядок, но он может отличаться от внутреннего порядка
  Hyperliquid и потому давать отличия открытия/закрытия.
- Минуты без сделок не заполняются искусственными ценами. Отчёт показывает
  отсутствующие минуты между первой и последней свечой, но не может отличить
  отсутствие торговли от дыр в архиве. Даты имени файла не доказывают полноту;
  первая и последняя минуты могут быть неполными.

README экспорта описывает структуру, но фактическую полноту большого файла
можно проверить только после его чтения. Тесты импорта используют небольшой
настоящий ZSTD Parquet с искусственными сделками; это не проверка купленного архива.

## Передача купленного файла в облако

Пользователь предпочитает облачную обработку. Для передачи большого файла
добавьте подписанную HTTPS-ссылку именно на Parquet в переменную
`OXARCHIVE_DOWNLOAD_URL` через настройки среды. Не публикуйте её в чате,
коде или журналах. Ключ аккаунта, пароль и карта загрузчику не нужны.

```sh
cd /workspace/my-project
.venv/bin/python download_archive.py --check-host
.venv/bin/python download_archive.py
.venv/bin/python archive_import.py data/0xarchive/export.parquet --output data/archive
```

Перед скачиванием разрешите точный hostname из `--check-host` в сетевых настройках,
сохраняя ранее разрешённые адреса. Скачивание сохраняет только имя сервера,
размер и вычисленную SHA-256, но не сам URL. Контролируются Content-Length,
HTTPS и сигнатуры Parquet. Издательский checksum пока неизвестен: локальная
SHA-256 не является доказательством его совпадения. Неполный файл остаётся
с расширением `.part` и не становится исходником для конвертера. Если нужно
повторить загрузку после сбоя, выберите новый путь `--output`; существующие
файлы не перезаписываются. По данным 0xArchive ссылки действуют 7 дней,
повторное открытие страницы заказа обновляет их в течение 30-дневного окна.
